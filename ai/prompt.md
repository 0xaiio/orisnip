# 2. 产品定位与核心创新

## 2.1 产品概念

《一刀万象》是一座可以玩的数字纸艺实验室。

用户通过折叠一张虚拟纸张，使用剪刀沿直线裁剪，再逐层展开纸张，欣赏和探索剪纸结果。

在此基础上，提供：

1. 折纸剪纸解谜游戏；
2. 数字对称剪纸创作；
3. AI 辅助创意设计；
4. 可保存、分享或打印的艺术作品。

## 2.2 核心体验

**Fold → Cut → Unfold → Wonder**

中文：

**折叠 → 剪切 → 展开 → 惊喜**

重点不在复杂操作，而在“简单操作产生复杂结果”的视觉和认知反差。

## 2.3 差异化价值

本产品不是：

- 静态的折纸教程；
- 只有几张预设图片的剪纸展示站；
- 仅仅调用大模型生成剪纸图片的 AI 套壳应用；
- 不考虑几何正确性的 SVG 视觉特效；
- 复制 Erik Demaine 现有谜题的游戏。

本产品必须做到：

- 所见即所得；
- 剪切结果来自真实几何计算；
- 每个可玩关卡都存在合法的已知解；
- 用户可以通过操作探索结果；
- 创作结果可以导出；
- AI 的作用真实、明确、可验证。

# 5. 数学与几何引擎：最重要的技术部分

这是整个产品的核心，优先级高于装饰性动画和 AI 功能。

## 5.1 基本对象

初始纸张建模为二维多边形区域 P。

第一版使用正方形，也可扩展至长方形。

设纸张经过若干次折叠，被划分为若干片区：

P_1, P_2, ..., P_n。

每一片区有一个从初始纸张坐标映射到折叠纸包坐标的保距变换：

f_i(x) = R_i x + t_i，

其中 R_i 是由反射和旋转构成的正交变换。

每个片区必须保留：

- 原始多边形；
- 正向变换；
- 逆变换；
- 折叠后多边形；
- 所属折叠层；
- 关联的折叠历史。

在支持范围内，所有折叠结果必须能通过这些变换重建。

## 5.2 第一版明确支持的折叠

为控制实现复杂度，P0 先支持：

- 不折叠；
- 沿水平中线对折；
- 沿垂直中线对折；
- 沿两条互相垂直的中线连续对折。

允许玩家选择预设折叠顺序，显示每一步折叠后的状态。

支持在折叠后的纸包坐标中调整直线剪切位置。

如果确实完成上述模式，再考虑：

- 一条预设斜折线；
- 其他经过合法性验证的简单折叠；
- 更高阶对称折叠。

不允许仅在视觉上生成一个任意折痕，却没有相应的几何映射。

## 5.3 剪切操作

“一刀挑战”必须严格限制为：

**在完全折叠后的平面纸包中，沿一条连续直线完成一次切割。**

切口可以由两端控制点定义。

必须明确：

- 剪切线的位置；
- 纸包的边界；
- 剪切线与纸张的实际交点；
- 被切割的纸张层；
- 剪切后保留与移除的区域。

为简化第一版，可以限定切线穿过纸包边界，并让用户明确选择或由关卡指定保留哪一侧。

零长度切线、不与纸张相交的切线、不满足关卡规则的切线必须正确处理。

用户不能在“一刀挑战”中画一个任意复杂的闭合路径并把它伪装成“一刀”。

## 5.4 展开算法

对每一片原始纸张区域 P_i：

1. 将该区域映射到折叠纸包坐标；
2. 根据剪切线和保留侧计算剪切后的多边形；
3. 使用 f_i 的逆变换映射回原始坐标；
4. 将各片展开后的区域合并；
5. 正确处理外轮廓、内部孔洞、多连通分量；
6. 得到完整展开图案。

请使用成熟、合适的二维多边形布尔运算库，或者自行实现经测试验证的限定范围算法。

对于布尔运算，注意坐标精度、重复顶点、共线边、零面积面片和多边形环方向等边界条件。

不要使用“直接生成一个看起来对称的 SVG”来取代几何展开。

## 5.5 必须实现的数学样例

初始纸张为以原点为中心的正方形：

P = [-a,a] × [-a,a]。

先沿 x=0 对折，再沿 y=0 对折，把四个象限折叠到第一象限。

此时折叠坐标为：

u = |x|，v = |y|。

在折叠纸包中，沿：

u + v = d

剪掉靠近原点的三角形区域：

u + v < d，

其中 0 < d < a。

完全展开后，纸张中心应形成菱形孔洞，其区域为：

|x| + |y| < d。

因此剩余纸张为：

P \ { (x,y) : |x| + |y| < d }。

这是第一个数学正确性黄金测试。

用户改变 d，菱形孔洞尺寸应连续变化。

## 5.6 剪纸艺术模式与一刀模式的严格区分

“一刀挑战”：

- 允许多次合法折叠；
- 最终只允许一条直线切割；
- 使用严格的折叠与展开算法。

“剪纸工坊”：

- 可以允许多次切口；
- 可以允许直线、三角形、圆形、叶片形等参数化切口；
- 可以使用反射对称和旋转对称生成纹样；
- 不必受 Fold-and-Cut 一刀定理限制。

对于仅通过数字对称变换生成、尚未验证实际折叠可实现性的纹样，必须标记为“数字对称艺术”，不能自动宣称其可以通过特定次数折叠和真实剪切制作。

只有经过实际折叠方案验证的作品，才允许提供对应的“实体折剪步骤”。

## 5.7 确定性与可复现性

相同输入必须产生相同的展开结果。

随机生成关卡使用可记录的 Seed。

项目内部应使用 TypeScript 类型系统明确建模：

- Paper
- PolygonRegion
- FoldOperation
- RigidTransform
- PaperLayer
- StraightCut

- UnfoldResult
- PatternDocument
- PuzzleLevel

# 6. 游戏模式的具体要求

## 6.1 关卡设计原则

至少完成 6 个精心设计、具有合法答案的关卡。

推荐关卡：

**关卡 1：剪掉一个角**

- 无折叠；
- 使用一条直线剪掉纸张角部；
- 介绍剪切线的控制方式。

**关卡 2：镜像魔法**

- 单次沿中线折叠；
- 观察镜像对称产生的切口图案；
- 学习对称轴。

**关卡 3：一刀成菱**

- 水平、垂直各对折一次；
- 剪掉折叠纸包内侧三角形；
- 展开得到中心菱形孔洞。

**关卡 4：偏移的秘密**

- 改变切线截距和角度；
- 产生与上一关不同的对称结果。

**关卡 5：同一目标，不同尝试**

- 给出一个经算法验证可实现的目标；
- 玩家自行调整切线；
- 比较不同结果。

**关卡 6：最终挑战**

- 给出由合法折叠与剪切方案正向生成的目标；
- 不直接给出答案；
- 允许多次尝试；
- 通关后展示目标生成过程。

可以增加扩展关卡，但不得用未经验证的目标图案凑数量。

## 6.2 关卡数据

每关应包含：

- ID；
- 名称；
- 简介；
- 难度；
- 初始纸张；
- 允许的折叠操作；
- 目标图案；
- 至少一种合法解；
- 提示；
- 数学知识点；
- 是否已通关。

游戏需要可以重复游玩。

## 6.3 评分算法

不要让大模型判断是否通关。

使用确定性的几何比较方法。

建议对目标纸张区域 T 和实际结果 A 计算：

Intersection over Union：

IoU = Area(A ∩ T) / Area(A ∪ T)。

如果可能，也计算对称差面积比：

Error = Area(A △ T) / Area(P)。

评分时说明：

- 几何上完全吻合；
- 在指定误差范围内接近；
- 与目标存在明显偏差。

允许对浮点计算误差设置合理容差。

避免仅用截图像素相似度判断几何正确性。

## 6.4 游戏反馈

至少包含：

- 成功反馈；
- 失败反馈；
- 当前几何相似度；
- 尝试次数；
- 重试；
- 查看提示；
- 查看解答；
- 下一关。

失败时不要只是显示“错误”，应说明结果在哪些位置与目标不同。

例如：“中心镂空区域比目标稍大，试着把剪切线往内移动。”

这种反馈应主要根据几何差异或结构化规则生成，而不是随意猜测。

## 6.5 过程回放

支持至少三个状态：

1. 完全展开；
2. 折叠后；
3. 完成剪切。

玩家可以返回初始状态、重新剪切、再次展开。

最好提供逐步折叠与展开的时间轴。

# 8. AI 灵感设计师：真实大模型集成

这是本项目的重要增强功能，但不允许影响核心几何引擎的正确性与可靠性。

## 8.1 接入方式

WorkBuddy 网站应用官方能力支持按需接入大模型。

请尝试使用 WorkBuddy 提供的网站应用大模型接入能力，完成实际调用。

要求：

- 尽可能使用 WorkBuddy 托管或官方支持的模型服务；
- 不要求最终用户自行填写 API Key；
- 不得将模型 API Key 暴露在浏览器 JavaScript 或静态配置文件中；
- 如果需要服务端代理，使用官方支持的安全后端能力；
- 对请求频率、输入长度和输出大小做合理限制；
- API 出错时显示明确提示并允许重试。

不要把 WorkBuddy 开发时使用的 AI 模型与发布应用实际可用的模型混为一谈。

如果无法真正接入运行时 AI：

- 保留核心游戏和创作功能；
- 可以隐藏 AI 功能入口或清楚显示暂不可用；
- 不得显示伪造的 AI 输出；
- 不得在作品介绍中宣称已完成真实 AI 集成。

## 8.2 AI 的功能定位

AI 不负责直接“绘制一张图片就算完成创作”。

它是一个**剪纸设计助手**，把模糊的文字创意转化为几何引擎可以执行的设计参数。

流程：

用户输入自然语言

→ 大模型分析主题、风格、对称偏好与图形元素

→ 生成结构化设计方案

→ JSON Schema 验证

→ 几何约束验证

→ 参数化纹样生成

→ 真实 SVG 图案

→ 用户继续编辑

## 8.3 示例输入

例 1：

“给我设计一朵适合春节装饰的八瓣红色窗花。”

例 2：

“我喜欢蓝白色的雪花，希望图案细腻但容易手工制作。”

例 3：

“设计一张有月亮和花朵元素的中秋窗花。”

例 4：

“我要一张简单、对称、适合小学生剪纸课堂的图案。”

## 8.4 结构化输出

请根据实际实现需要定义 JSON Schema。

可参考如下结构：

{
  "theme": "mid_autumn",
  "style": "traditional_papercut",
  "symmetry": {
    "type": "radial",
    "order": 8
  },
  "palette": {
    "paper": "#B93645",
    "background": "#F8F3E9"
  },
  "motifs": [
    {
      "type": "petal",
      "size": 0.45,
      "rotation": 0
    },
    {
      "type": "diamond",
      "size": 0.18,
      "rotation": 30
    }
  ],
  "complexity": "medium",
  "description": "一张以中秋节为主题的对称窗花"
}

这是结构设计示意，不是可以绕过几何验证直接执行的最终 schema。

实际实现时，需要为各字段定义严格类型、枚举、取值范围、最大数量和缺省值。

对于系统暂时不支持的“兔子”“龙”“复杂文字”等元素，不要声称能够精确实现。

可以提供风格化的几何近似，或者明确告诉用户当前只支持抽象花瓣与几何纹样。

## 8.5 模型职责边界

模型可以：

- 生成创意方向；
- 选择纹样风格；
- 推荐颜色；
- 提出对称模式；
- 选择已实现的几何元素；
- 解释作品的数学与艺术特点；
- 生成简短的作品标题与分享文案。

模型不可以：

- 伪造折纸定理；
- 未经算法验证断言任意图案可被一刀剪出；
- 替代几何求解器；
- 将任意图片当作合法物理折叠方案；
- 编造不存在的学术出处；
- 绕过 JSON 和几何验证。

## 8.6 AI 故障降级

模型超时、额度不足、网络错误或输出不合规时：

- 显示清晰错误提示；
- 不丢失当前作品；
- 允许用户重试；
- 提供若干本地内置创意模板；
- 几何引擎继续正常运行。

不进行自动无限重试。

# 14. 严格的软件测试要求

必须实际运行测试，而不是仅报告“测试通过”。

## 14.1 几何测试

测试至少包括：

1. 无折叠、无剪切，结果与原纸相同。
2. 一次镜像折叠后展开，原始形状恢复。
3. 两次正交折叠后展开，原始形状恢复。
4. 两次正交折叠与中心三角形剪切，展开后出现菱形孔洞。
5. 改变切线截距后，孔洞尺寸正确变化。
6. 切线不与纸张相交时，操作被合理拒绝或保持不变。
7. 零长度切线得到明确错误。
8. 对称操作得到正确的对称结果。
9. 所有结果均位于原纸张范围内。
10. 剪切后不能无故增加纸张面积。
11. 重复同样操作得到相同结果。
12. 多边形退化情况不会导致崩溃。

## 14.2 属性测试

在可行范围内自动生成参数，验证：

- 剪切后面积不增加；
- 展开结果不超出纸张原始边界；
- 反射变换保持距离和面积；
- 逆变换恢复顶点位置；
- 对于预设对称折叠，最终区域满足相应对称性；
- 同一模型输入结果可复现。

## 14.3 游戏测试

- 每个关卡都有合法解；
- 使用已知标准解能够成功通关；
- 明显错误的解不能被判为通关；
- 评分结果在合法范围内；
- 提示、重试、重置可用；
- 保存和恢复关卡进度可用。

## 14.4 创作测试

# 16. 开发中的特殊约束

## 16.1 科学准确性

本项目受到 MIT Erik Demaine 的计算折纸、Fold-and-Cut 和几何谜题研究启发。

相关参考：

https://erikdemaine.org/

https://erikdemaine.org/fonts/simplefoldcut/

https://origamisimulator.org/

不直接复制第三方谜题、课程图片、软件代码或图形素材，除非明确核对授权。

在数学介绍中正确区分：

- 一般平折；
- 简单折叠；
- 单次直线切割；
- 多次切割；
- 数字对称图案生成。

不得将受限几何引擎宣传为任意多边形一刀剪切问题的完整求解器。

## 16.2 产品诚实性

所有可点击按钮必须执行真正的功能。

禁止：

- 装饰性假按钮；
- 假装实时计算的固定动画；
- 永远相同的“AI 生成”结果；
- 使用固定图片冒充任意参数编辑；
- 伪造用户作品；
- 伪造排行榜；
- 伪造测试报告；
- 伪造线上部署成功状态。

## 16.3 隐私与安全

默认不收集用户个人信息。

本地创作优先存储在浏览器内。

如果使用云端模型：

- 告知用户哪些文本会发送到模型服务；
- 不上传整个私人作品库；
- 不暴露 API Key；
- 不储存不必要的个人数据；
- 不允许模型输出注入任意代码。

外部素材、字体与软件依赖必须检查许可证。

## 17.4 30–60 秒演示脚本

展示顺序：

0–5 秒：一张普通纸出现在屏幕上。

5–12 秒：用户折叠纸张，调整剪切线。

12–20 秒：剪刀切下，纸张层层展开，出现图案。

20–35 秒：演示游戏挑战及目标匹配。

35–48 秒：进入剪纸工坊，制作一张漂亮的窗花。

48–60 秒：展示 AI 创意或导出实体模板的真实能力，最后出现作品名称和体验链接。

若 AI 或模板功能未实际实现，则用已完成的创作与导出功能替代。
